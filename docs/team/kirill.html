4. Архитектурный поток данных

main() → SlotlyApp
  initState: AppDependencies.demo()   ← единственное место выбора реализаций
     ├─ AppController                 тема / вкладка
     ├─ LifecycleLogger               подписан на AppLifecycleListener с запуска
     ├─ BookingsController(InMemoryBookingRepository)
     └─ …
  build: AppScope → ListenableBuilder(AppController) → MaterialApp(themeMode)
           └─ WelcomeScreen → pushReplacement → HomeShell
                 IndexedStack[ CatalogScreen | BookingsScreen | ProfileScreen ]
                 NavigationBar.onDestinationSelected → AppController.selectTab
  dispose: AppDependencies.dispose()  → LifecycleLogger.dispose() → listener.dispose()

Платформа Android ──flutter/lifecycle──► ServicesBinding (достраивает hidden)
  ──► AppLifecycleListener.onStateChange ──► LifecycleLogger._record
  ──► notifyListeners ──► DiagnosticsScreen (ListenableBuilder)

5. Основные алгоритмы

Нумерация журнала

Номер события = длина журнала + 1, поэтому после очистки нумерация начинается с 1. Первое событие — состояние, которое уже было активно при создании логгера (WidgetsBinding.instance.lifecycleState), оно помечается как начальное.

Системная кнопка Back в оболочке

PopScope(
  canPop: current == HomeTab.services,
  onPopInvokedWithResult: (didPop, _) {
    if (!didPop) controller.selectTab(HomeTab.services);
  },
  …
)

Отмена свайпом без «висящего» Dismissible

confirmDismiss ждёт диалог и отмену через контроллер и всегда возвращает false. Список перестраивается по данным контроллера, поэтому карточка исчезает, если отмена подтверждена, и возвращается, если нет.

После успешной записи

AppRoutes._showBookingResult запоминает ScaffoldMessenger и AppController, делает popUntil(isFirst), переключает вкладку на «Записи» и показывает SnackBar (с напоминанием, если включены демо-уведомления).

9. Сценарий демонстрации

  1. Запустить приложение, на welcome выбрать категорию — подпись меняется (setState).
  2. «Посмотреть услуги» → каталог с фильтром. Показать, что Back на «Услугах» закрыл бы приложение (welcome заменён).
  3. Профиль → «Диагностика»: состояние resumed, событие #1.
  4. Home → вернуться: inactive → hidden → paused → hidden → inactive → resumed с временем.
  5. Очистить журнал: empty state и SnackBar.
  6. После записи (её показывает Влад) — вкладка «Записи»: tap, long press, свайп → «Не отменять», свайп → «Отменить запись», вкладка «Отменённые».
  7. Профиль → тёмная тема. Системная Back на «Профиле» → «Услуги».
  8. Терминал: flutter test и страница CI в документации.

10. Короткая защита (от первого лица)

Я отвечаю за каркас приложения и его сборку. Корневой виджет создаёт все зависимости в одном месте — AppDependencies — и освобождает их при закрытии. Экраны получают данные через конструкторы, а связи между экранами описаны в routes.dart, поэтому каждый экран можно протестировать отдельно.

Для первой лабораторной я сделал журнал жизненного цикла. Логгер создаётся при запуске и подписан через AppLifecycleListener, поэтому ловит даже ранние события. На Android Flutter сам добавляет состояние hidden между inactive и paused; при закрытии из недавних мы видели detached в logcat, но при аварийном завершении его может не быть.

Во второй лабораторной на мне «Мои записи»: tap открывает детали, долгое нажатие — меню, свайп — только запрос отмены. Запись не удаляется, а получает статус «отменена». И ещё я настроил CI, который на каждый push проверяет формат, анализатор, тесты и собирает APK.

  3. Почему в журнале есть hidden, если Android такого не присылает?
  4. Где и зачем вызывается dispose у AppLifecycleListener?
  5. Чем AppLifecycleState отличается от колбэков Activity?
  6. Почему welcome открывается через pushReplacement?
  7. Как вкладки сохраняют состояние при переключении?
  8. Почему свайп не удаляет запись сразу и как это реализовано?
  9. Как экраны получают зависимости и почему не синглтоны?
  10. Что проверяет CI и почему он не обновляет golden-файлы?

12. Краткие ответы

  1. Linux kernel → HAL → нативные библиотеки и ART → application framework → приложения. Flutter — часть приложения: Activity и embedder на Kotlin/Java, Engine в нативной библиотеке, UI рисует сам.
  2. Widget — неизменяемое описание; Element — экземпляр в дереве и хранитель State; RenderObject — layout, paint, hit test.
  3. ServicesBinding достраивает промежуточные состояния, чтобы последовательность переходов была одинаковой на всех платформах.
  4. В LifecycleLogger.dispose(), вызывается из AppDependencies.dispose() в SlotlyApp.dispose. Иначе подписка осталась бы на binding и обращалась к уничтоженному объекту.
  5. Это состояние всего приложения, обобщённое для всех платформ; соответствие колбэкам Activity приблизительное.
  6. Чтобы Back на главном экране закрывал приложение, а не возвращал на приветствие.
  7. IndexedStack держит все три вкладки в дереве, их Element и State не уничтожаются.
  8. confirmDismiss показывает диалог и всегда возвращает false; при подтверждении статус меняется через контроллер, список перестраивается.
  9. Маршруты берут их из AppScope и передают в конструкторы. Так видно, от чего зависит экран, и тесты подставляют свои реализации.
  10. Формат, flutter analyze, все тесты с покрытием и сборку debug APK. Golden-файлы только сравниваются: эталон обновляют намеренно и проверяют глазами.

13. Типичные ошибки

  • Поставить AppBar внутрь Column без ограничения высоты — layout падает, нажатия перестают работать (мы так и поймали ошибку тестом).
  • Забыть dispose у listener или контроллера.
  • Возвращать true из confirmDismiss и менять данные асинхронно — ошибка «dismissed Dismissible is still part of the tree».
  • Использовать BuildContext после await без проверки mounted.
  • Описывать Flutter lifecycle как точную копию onStart/onStop.

14. Если демонстрация не работает

  • В журнале только #1: приложение не сворачивалось — нажмите Home и вернитесь; проверьте adb logcat -s flutter.
  • Нажатия не работают после изменений в коде: смотрите консоль flutter run на исключения layout.
  • Эмулятор завис: adb kill-server && adb start-server, перезапуск AVD с флагом -no-snapshot-load.
  • Нет устройства: скриншоты в обзоре проекта и запуск тестов модуля.
