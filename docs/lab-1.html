1. Первое Flutter-приложение

Точка входа — lib/main.dart: функция main() вызывает runApp(SlotlyApp()). Корневой виджет SlotlyApp создаёт зависимости приложения, настраивает Material 3 тему, русскую локализацию и открывает WelcomeScreen.

Welcome-экран — StatefulWidget. При нажатии на категорию вызывается setState, Flutter заново вызывает build, и выбранный чип подсвечивается, а подпись под чипами меняется:

void _toggleCategory(ServiceCategory category) {
  setState(() {
    _selectedCategory = _selectedCategory == category ? null : category;
  });
}

Кнопка «Посмотреть услуги» передаёт выбранную категорию наружу через callback, а SlotlyApp выполняет Navigator.pushReplacement. Используется именно replacement: после перехода кнопка Back на главном экране закрывает приложение, а не возвращает на приветствие.

2. Теоретическая часть

Android как целевая платформа

Android — операционная система для мобильных устройств на основе ядра Linux. Каждое приложение распространяется как APK или AAB, устанавливается системой и запускается в отдельном процессе под собственным Linux-пользователем (песочница). Точкой входа для пользователя служит Activity, описанная в AndroidManifest.xml. Доступ к камере, сети, уведомлениям и другим ресурсам выдаётся через разрешения и системные сервисы.

Для Slotly целевая платформа задана в android/app/build.gradle.kts: applicationId = "kz.slotly.mobile", minSdk 24 (Android 7.0), targetSdk и compileSdk 36 (Android 16).

Как Flutter работает поверх Android

  1. Android запускает процесс приложения и создаёт MainActivity. В Slotly это class MainActivity : FlutterActivity() на Kotlin — обычная Android Activity.
  2. FlutterActivity (Android embedder) создаёт FlutterEngine и FlutterView — поверхность, на которой рисует Flutter.
  3. Flutter Engine (C++, библиотека libflutter.so) запускает Dart-код приложения. В debug-сборке Dart выполняется в JIT-режиме (это даёт hot reload), в release — заранее скомпилирован в машинный код (libapp.so).
  4. Фреймворк Flutter (Dart) строит дерево виджетов, вычисляет layout и формирует сцену. Engine растеризует её через Impeller (Vulkan или OpenGL ES) прямо в поверхность FlutterView. Системные View Android для кнопок и списков не используются.
  5. События касания, клавиатура, изменения размеров экрана, доступность и жизненный цикл приходят из Android в embedder и пересылаются в Dart через platform channels. Например, состояние жизненного цикла приходит по каналу flutter/lifecycle.

Благодаря такому разделению setState пересоздаёт только лёгкие виджеты, а дорогие RenderObject переиспользуются. Это объясняет, почему в IndexedStack вкладки сохраняют состояние: их Element и State не удаляются при переключении.

Flutter Engine и Android embedder

  • Flutter Engine — кроссплатформенное ядро на C++: Dart VM/рантайм, рендерер Impeller, раскладка текста, обработка platform channels.
  • Android embedder — код на Java/Kotlin из пакета io.flutter.embedding.android: FlutterActivity, FlutterView, FlutterEngine. Он связывает Engine с Activity, окном, вводом, клавиатурой, accessibility и жизненным циклом Android.

Почему Flutter не заменяет Android

Flutter заменяет только UI-слой и язык прикладной логики. Всё остальное остаётся Android: процесс и песочница Linux, AndroidManifest.xml, Activity и её жизненный цикл, разрешения, ART для Kotlin-кода embedder, системные сервисы и Gradle-сборка APK. Доступ к возможностям ОС (камера, уведомления, файлы) Flutter получает через platform channels и плагины, которые внутри вызывают обычные Android API.

3. Жизненный цикл

Flutter описывает жизненный цикл всего приложения через AppLifecycleState. Это не копия колбэков Activity: состояния обобщены для Android, iOS, desktop и web, а переходы зависят от платформы.

СостояниеСмыслКогда наблюдается на Android
resumedПриложение видно и принимает вводПриложение на переднем плане
inactiveВидно, но не принимает вводОткрыт экран недавних приложений, шторка, системный диалог; начало сворачивания
hiddenИнтерфейс скрытAndroid такого состояния не присылает: фреймворк добавляет его сам между inactive и paused
pausedПриложение в фоне, не видноПосле нажатия Home или переключения на другое приложение
detachedEngine работает без видимого окнаActivity уничтожена, например при закрытии приложения из списка недавних

Соответствие с onResume/onPause/onStop/onDestroy только приблизительное. Если процесс завершается аварийно или убивается системой из-за нехватки памяти, часть событий (в том числе detached) может не прийти. Поэтому сохранять важные данные нужно при переходе в paused, а не надеяться на detached.

Реализация

LifecycleLogger — ChangeNotifier, который создаётся один раз при старте в AppDependencies. Поэтому события записываются, даже если экран «Диагностика» ещё не открыт.

LifecycleLogger({this.clock = systemClock}) {
  final initialState = WidgetsBinding.instance.lifecycleState;
  if (initialState != null) _record(initialState, isInitial: true);
  _listener = AppLifecycleListener(onStateChange: _record);
}

@override
void dispose() {
  _listener.dispose();
  super.dispose();
}

AppLifecycleListener подписывается на WidgetsBinding при создании. Без вызова dispose() подписка осталась бы активной и вызывала бы notifyListeners у уничтоженного объекта. Это поведение проверяет тест dispose releases the AppLifecycleListener.

Каждое событие дополнительно пишется в системный лог в debug-сборке, поэтому переходы перед закрытием процесса можно увидеть командой adb logcat -s flutter.

Фактическая последовательность на эмуляторе

Записано 5 октября 2026 года на эмуляторе Android 16 (API 36, arm64) с debug-сборкой Slotly:

4. Сценарий демонстрации

  1. Запуск. Запустить приложение, выбрать категорию на welcome (подпись под чипами меняется — это setState), нажать «Посмотреть услуги». Открыть вкладку «Профиль» → «Диагностика». В журнале есть событие #1.
  2. Сворачивание. Нажать Home. Вернуться в приложение: в журнале появились inactive, hidden, paused.
  3. Возврат из recent apps. Открыть список недавних приложений и выбрать Slotly: hidden, inactive, resumed.
  4. Переключение на другое приложение. Открыть, например, «Настройки».
  5. Возвращение. Вернуться в Slotly: видна полная последовательность ухода и возврата, у каждого события номер и время.
  6. Закрытие и повторный запуск. Закрыть приложение свайпом в списке недавних и запустить снова. Журнал хранится в памяти, поэтому начинается заново с #1. События перед закрытием показать в терминале: adb logcat -s flutter.

Кнопка с иконкой корзины очищает журнал. После очистки показывается empty state, а нумерация начинается с #1.
