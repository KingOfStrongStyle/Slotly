План развития

Что нужно, чтобы учебный MVP стал коммерческим продуктом, и какие текущие границы модулей это позволяют. Ничего из перечисленного в MVP не реализовано.

НаправлениеРешениеОпора в текущем коде

Расписание сотрудниковПравила рабочего времени, перерывы, отпуска; слоты считает серверМетод fetchTimeSlots; DemoSchedule заменяется ответом API

Набросок API-контракта

GET  /api/v1/businesses/{id}/services/                 → [Service]
GET  /api/v1/services/{id}/slots/?specialist=&date=     → [{start_at, is_available}]
GET  /api/v1/me/bookings/                               → [Booking]
POST /api/v1/me/bookings/  {service_id, specialist_id, start_at, comment}
                                                        → 201 Booking | 409 slot_unavailable
POST /api/v1/me/bookings/{id}/cancel/                   → 200 Booking (status=cancelled)
GET  /api/v1/queue/tickets/{number}/                    → 200 Ticket | 404

Миграция InMemoryBookingRepository на HTTP

  1. Добавить пакет http (или dio, если понадобятся интерсепторы авторизации).
  2. Создать lib/features/booking/data/http_booking_repository.dart: class HttpBookingRepository implements BookingRepository.
  3. Добавить преобразование JSON ↔ модели (fromJson/toJson рядом с DTO в data/, доменные модели остаются чистыми).
  4. Преобразовать ответы API в доменные исключения: 409 → SlotUnavailableException, 404 → BookingNotFoundException.
  5. В AppDependencies добавить фабрику AppDependencies.production(apiBaseUrl); демо-фабрику оставить для тестов и демонстраций.
  6. Экраны, BookingsController и тесты экранов не меняются; добавляются тесты HTTP-слоя с подменённым клиентом.

Какие границы модулей это позволяют

  • Репозитории отделяют экраны от источника данных — backend подключается без переписывания UI.
  • Доменные модели и правила (BookingDraft, TicketEntry, GestureClassifier) не зависят от Flutter и переиспользуются при любых изменениях интерфейса.
  • AppDependencies — одно место выбора реализаций для разных окружений.
  • Feature-first папки позволяют добавлять роли сотрудника и владельца как новые модули.
  • AppStrings и Material 3 тема из одного seed-цвета упрощают локализацию и брендирование под конкретный бизнес.
