План развития (фаза B)

Что нужно, чтобы локальный MVP стал серверным продуктом. Ничего из перечисленного не реализовано; текущий код подготовил границы, через которые это подключается.

Версия 0.2.0 работает только на устройстве. Демо-вход, проверка прав, напоминания и аналитика выполняются на телефоне и не являются production-backend. Ниже — что именно заменит каждую часть.

2. Аутентификация и права

  • Пароли — только на сервере, Argon2id; вход по телефону с одноразовым кодом как альтернатива.
  • Access token 5–15 минут в памяти, refresh token в Android Keystore (secure storage), ротация при каждом обновлении, отзыв сессий.
  • Каждая операция проверяется сервером: DRF permission-классы по той же матрице, queryset всегда фильтруется по организации пользователя; мультитенантность — organization_id в каждой таблице, при росте — Row Level Security.
  • OrganizationMembership с ролями владелец / администратор / мастер (сейчас — одно поле organizationId).
  • Rate limiting входа и чувствительных операций, журнал аудита действий владельцев.
  • В приложении меняются AuthRepository и SessionController; клиентская AccessPolicy остаётся для скрытия кнопок.

3. Фотографии

  • Объектное хранилище (S3-совместимое), загрузка напрямую с телефона по presigned URL, сервер фиксирует только метаданные.
  • Серверная проверка типа и размера, генерация миниатюр, CDN.
  • В приложении — новая реализация PhotoStorage; в модели фото вместо пути к файлу — URL.

4. Уведомления

  • FCM, хранение device token на сервере, обновление при ротации и удаление при выходе.
  • Серверный планировщик (Celery beat), идемпотентные задачи «запись + вид напоминания», повтор при сбое.
  • Уведомления об изменениях, сделанных владельцем, доставка на все устройства и после переустановки.
  • Метрики доставки и ошибок. Локальные напоминания остаются как резерв без сети.

5. Аналитика

  • Ежедневные агрегаты по организации (материализованные представления или таблица агрегатов), пересчёт фоновой задачей.
  • Журнал событий избранного и визитов вместо текущего состояния — точная история добавлений и повторных визитов.
  • AnalyticsRepository получает готовые числа; формулы из «Аналитики» переносятся на сервер вместе с тестами.

Порядок

  1. API каталога и записей + серверный вход; HTTP-реализации двух репозиториев.
  2. Членство и роли, серверные права, отзывы и избранное.
  3. Объектное хранилище фото, кабинет владельца на API.
  4. FCM и серверный планировщик.
  5. Серверная аналитика, аудит, мониторинг, публикация.
