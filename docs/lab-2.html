Лабораторная работа №2

Элементы интерфейса, ввод данных, компоновка, маршруты, диалоги, уведомления, списки, вкладки и свайпы на примере сценария записи на услугу.

Версия 0.2.0. Страница описывает состояние на момент сдачи (тег lab-2). Все требования выполняются и сейчас: поиск и фильтр — в каталоге, режим «Услуги»; детали услуги получают Service через конструктор; форма записи сохранила валидацию и диалог, добавился выбор варианта цены. «Мои записи» — три вкладки (Активные, Прошедшие, Отменённые); свайп влево — отмена, вправо — перенос, оба с подтверждением. Демо-уведомления заменены настоящими напоминаниями; InMemoryBookingRepository — локальной базой LocalBookingRepository; HomeShell — оболочками ClientShell и OwnerShell. Для демонстрации войдите как aliya / aliya-demo.

Ответственные: каталог, детали услуги, профиль и общие компоненты — Ян; модели, репозиторий, форма записи и валидация — Влад; навигация, маршруты, «Мои записи» и интеграция — Кирилл.

Навигация

WelcomeScreen
  └─ pushReplacement → HomeShell (Scaffold + NavigationBar + IndexedStack)
        ├─ [0] CatalogScreen ── push → ServiceDetailsScreen(service)
        │                                   └─ push → BookingFormScreen(service)
        │                                          └─ после подтверждения: popUntil(first) + вкладка «Записи»
        ├─ [1] BookingsScreen (TabBar: Активные / Отменённые)
        └─ [2] ProfileScreen ── pushNamed → /diagnostics, /gesture-lab, /ticket-check-in
  • NavigationBar (Material 3) переключает три вкладки. Тела вкладок лежат в IndexedStack, поэтому текст поиска, выбранная категория и прокрутка сохраняются при переключении.
  • Один Scaffold на оболочку. Вкладки не создают собственный Scaffold: у каталога и профиля SliverAppBar, у записей — NestedScrollView со SliverAppBar и TabBar. SnackBar показывается над нижней навигацией.
  • Системная кнопка Back. На вкладках «Записи» и «Профиль» Back сначала возвращает на «Услуги» (PopScope), на «Услугах» — закрывает приложение. На вложенных экранах Back закрывает экран.
  • Маршруты описаны в lib/app/routes.dart. Экраны без параметров — именованные маршруты. Экраны с данными получают объект через типизированную фабрику: AppRoutes.serviceDetails(service) создаёт ServiceDetailsScreen(service: service). Объект Service передаётся через конструктор, без повторного поиска по id.

Каталог

Фильтрация — чистая функция filterServices в доменном слое. Поиск не зависит от регистра, игнорирует пробелы по краям и считает «ё» и «е» одной буквой:

String normalizeSearchText(String value) =>
    value.trim().toLowerCase().replaceAll('ё', 'е');

Если ничего не найдено, показывается empty state с кнопкой «Сбросить фильтры».

Форма записи и валидация

  1. Пользователь выбирает специалиста. Если у услуги один специалист, он выбран сразу.
  2. Дата выбирается в ленте из 14 дней, по умолчанию — сегодня.
  3. Слоты загружаются через BookingsController.fetchTimeSlots. Занятые слоты зачёркнуты и отключены: их нельзя выбрать.
  4. Комментарий необязателен. Если он длиннее 200 символов, под полем появляется ошибка.
  5. Пока данных не хватает, кнопка «Продолжить» отключена, а над ней написано, чего не хватает: «Чтобы продолжить, выберите: специалиста, время».
  6. Кнопка открывает AlertDialog с итоговыми данными. «Изменить» закрывает диалог без сохранения, «Подтвердить» создаёт запись через репозиторий.
  7. После успеха пользователь попадает на вкладку «Записи» и видит SnackBar «Вы записаны: …». Если время успели занять, показывается сообщение и расписание перезагружается.

Правила формы вынесены в класс BookingDraft и проверяются unit-тестами без виджетов. Например, смена специалиста или даты сбрасывает выбранное время, потому что старый слот может отсутствовать в новом расписании.

Мои записи: списки, вкладки и свайпы

  • Сортировка: активные — от ближайшей к дальней, отменённые — от последней.
  • Tap открывает нижнюю панель с деталями.
  • Long press открывает меню действий: «Подробнее» и «Отменить запись».
  • Swipe влево показывает красный фон «Отменить» и диалог подтверждения.

Мгновенного необратимого удаления нет. confirmDismiss всегда возвращает false:

confirmDismiss: (_) async {
  await confirmCancel();   // диалог + отмена через контроллер
  return false;            // Dismissible сам ничего не удаляет
},

Если пользователь подтвердил отмену, контроллер меняет статус записи на cancelled, список перестраивается, и карточка переходит на вкладку «Отменённые». Если отказался, карточка возвращается на место. Так обходится известная проблема Dismissible: виджет нельзя оставлять в дереве после onDismissed, а асинхронное обновление данных не успело бы его убрать.

Состояние и данные

  • AppController (ChangeNotifier) — тема, демо-уведомления, текущая вкладка.
  • BookingsController (ChangeNotifier) — общий список записей, загрузка, создание и отмена.
  • BookingRepository — контракт источника данных, сейчас реализован InMemoryBookingRepository.
  • Экраны подписываются через ListenableBuilder и не изменяют общий список напрямую.

Адаптивность и доступность

  • На ширине больше 640 dp контент центрируется (responsiveGutter, ResponsiveCenter).
  • Размеры не фиксируются по высоте: карточки и чипы растут при увеличенном шрифте. Тест text_scale_test.dart проверяет основные экраны при масштабе шрифта 2.0.
  • Кнопки не ниже 48 dp, у карточек и слотов есть Semantics (занятый слот озвучивается как «14:00, Занято»).
  • Тёмная тема генерируется из того же seed-цвета.

Сценарий демонстрации

  1. Welcome → «Посмотреть услуги».
  2. В поиске набрать «СТРИЖ» — остаётся «Мужская стрижка». Набрать «луна» — empty state, «Сбросить фильтры».
  3. Открыть «Мужская стрижка» → «Записаться». Показать отключённую кнопку и подсказку.
  4. Выбрать специалиста, «Завтра», показать зачёркнутые слоты, выбрать свободное время.
  5. «Продолжить» → диалог → «Изменить» (ничего не создано) → снова «Продолжить» → «Подтвердить».
  6. Открылась вкладка «Записи» и SnackBar. Создать ещё одну запись на более раннюю дату — показать сортировку.
  7. Tap по записи — детали. Long press — меню действий.
  8. Свайп влево → «Не отменять» (запись осталась) → снова свайп → «Отменить запись». Показать вкладку «Отменённые».
  9. Профиль → включить тёмную тему.
